# `evidence_quality = Misleading` — 偵測

English: [MISLEADING.md](MISLEADING.md)

`Misleading`(漂綠)是 evidence_quality 中最稀有的類別 —— 每 1000 段約 1–3 個 —— 監督式 BERT head
幾乎不會輸出。因此我們用一個**高精準度的 LLM 偵測器**找出候選段落,最終提交再套用一份小型固定
override 清單(`config/misleading_overrides.txt`)。

## 定義(偵測器提示詞 v3)

只有當「承諾(promise)是具體/可驗證的主張」但其「佐證(evidence)」用以下三種模式之一未能支持它時,
才算 `Misleading`。偵測器被要求對幾乎所有段落預設答「No」,並在判斷主題相符前先 GROUND 關鍵詞
(公司別名、框架名稱、計畫名稱):

- **Pattern A — 窄承諾 + 不同主題的證據。** promise 是單一具體可驗證主張(某目標/認證/數字),但
  evidence 的核心是真正不同的主題(例如 SBTi 淨零目標 ↔ 一份雜項得獎名單)。
- **Pattern B — ESG 指標被挪用於非 ESG 目的。** ESG 指標被當成薪酬/獎金觸發條件,或拿來包裝純治理/
  財務機制。
- **Pattern C — 空洞(講了等於沒講),嚴格。** promise 與 evidence 皆為純通用八股、零具體內容。嚴格:
  只要含任何具體元素(數字、具名計畫、具體行動、認證)⇒ Clear/Not-Clear,不是 Misleading。

輸出格式(每個 id):`{"m":"Yes"|"No","c":"high"|"med"|"low","pat":"A"|"B"|"C"|"-","why":"<=8 字"}`。

## 使用模型

候選段落由多個 LLM 各自評分並交叉比對:

| 角色 | 模型 |
|---|---|
| 主要語意掃描(經 OpenRouter API) | `google/gemini-3.1-pro-preview`(temperature 0.2) |
| agent 重讀 / 評分 | Claude **Opus 4.8** |
| 交叉比對 | `deepseek-reasoner`、Qwen、GLM |

(API 金鑰皆由環境變數讀取 —— 本 repo 不存放任何金鑰。)

## 最終 override 清單(提交用)

最終提交使用的 override 清單,即 [`../config/misleading_overrides.txt`](../config/misleading_overrides.txt)
中的五個 id:

```
12772   12599   12306   12606   12743
```

這些由 `pipeline/build_tapt_hybrid.py --misleading ...` 套用為固定 override
(promise=Yes、evidence=Yes、quality=Misleading)。此清單是建構器的設定輸入;它與上面的偵測器候選有
重疊(例如 12772、12599),但並不等同於任何單一次偵測器執行的 top-k。
